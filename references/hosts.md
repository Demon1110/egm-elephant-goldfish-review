# 宿主适配与零上下文验证

“金鱼看不到前面对话”这句话没法直接证明，只能拆成能查的子命题：

1. 评审者是不是宿主新建的、与父对话无共享轮次的代理？
2. 它能不能写文件（必须不能）？
3. 它的可读范围是否被限制在评审包白名单？
4. 宿主有没有偷偷塞进项目级指令文件（AGENTS.md / CLAUDE.md / GEMINI.md）？
5. 派发时我们自己有没有把背景写进 prompt？

这五条任何一条失守，报告结论就只能当“内部自查”，不能当第三方评审。

## 一、隔离能力分级

| 级别 | 形态 | 能否叫金鱼评审 | 记录用 `isolation.mode` |
| --- | --- | --- | --- |
| L1 | 全新子代理，只读工具，无父对话、无项目指令注入 | 可以 | `fresh-subagent` |
| L2 | 全新子代理，但宿主会把本次任务的原始请求带进去 | 可以，但要在报告里标注 | `fresh-subagent-query-leak` |
| L3 | 同一会话内“换个角色重读” | **不可以** | `same-context-degraded`（需人批准） |
| L4 | 宿主根本不支持派子代理 | 停下，问用户 | 不适用 |

L2 是当前豆包环境的默认形态：子代理不继承父对话，但框架会把**用户本轮原始请求**作为它的第一条消息传进去。这不是父对话泄漏，但会把“用户当时怎么描述需求”带进评审者视野——如果用户在请求里写了方案细节，评审者就被锚定了。

**对策**：派发前把一切背景写进 `design_draft.md` / `review_packet.md`；用户的请求只保留“评审这份文档”这类最小指令。已经写在对话里的方案细节，不要指望子代理看不到。

## 二、各宿主适配

| 宿主 | 关键字段 | 已知漏点 |
| --- | --- | --- |
| 豆包（当前环境） | 用 `create_agent` 派 `OrganizerAgent`；`hint` 里只放 packet 路径、角色、报告路径、禁令 | 原始请求透传（L2）；子代理仍可能自行扩展任务，需在 hint 里写死“只做评审” |
| Claude Code | 子代理 `tools: [Read, Grep, Glob]`、`omitClaudeMd: true`、`model: inherit` | 无（`omitClaudeMd` 已排除项目指令文件） |
| Codex CLI | `fork_context: false`、`fork_turns: "none"` | 仍会注入项目级/用户级 `AGENTS.md`，属指令泄漏，非对话泄漏 |
| Cursor | `readonly: true`、`permissionMode: readonly` | 本项目未验证项目规则文件是否排除，按 L2 记 |
| Copilot | `tools: ["read","search"]`、`include-custom-instructions: false`、`user-invocable: false` | 需确认自定义指令确实未注入 |
| Antigravity | `agy plugin install` | 会注入项目 `AGENTS.md` 与 `GEMINI.md` |

不确定的宿主，按 L2 记录并写进报告元信息表；不要凭“应该没问题”写成 L1。

## 三、派发口令（严格照抄结构）

派给子代理的消息里只允许出现四类内容：**角色、可读文件、输出位置、禁令**。

```
你是 EGM 评审者 egm-{persona}，步骤 {step}，范围 {range}。
只读：{packet 路径}，以及其中“允许阅读清单”列出的文件。
只写：{报告路径}（不得修改任何其他文件）。
规则：按评审包第 5、6 节执行；不得读取清单外文件；找不到必需文件时报 incomplete，不要给结论。
完成后只回复一句话：报告已写入 {报告路径}，共 N 条 finding。
```

不允许出现：设计背景、前几轮结论、你希望它重点看哪里、其他评审者的意见、用户的原始需求描述。

派 Step 5 时可以一次派两个（zoom_out 与 inventive_catalyst），但**分别给不同报告文件**，互相不可见。派 Step 6 时不要附上 Step 5 的任何结论——理解性角色必须“什么都不知道”。

## 四、泄漏探针（每轮抽一次）

派发后在报告之外，让对方回答一个**只存在于对话、不存在于文档**的事实，例如：

- “设计定稿前，被否决的第二个方案叫什么？”
- “用户在哪一句话里提到过截止时间？”

答得出来 → 存在泄漏；答不出来 → 至少说明文档之外的信息没有进来。
把探针问题和结果记进报告元信息表的备注或台账“备注”列。这是唯一能低成本验证隔离的方法。

## 五、降级流程

宿主不支持子代理，或子代理无法只读时：

1. **默认停下**，告诉用户：“当前宿主没有可隔离的子代理，同上下文自评不算金鱼评审。要继续的话只能降级，结论只能当自查。”
2. 用户明确同意后，在 `manifest.json` 里写 `"mode": "same-context-degraded", "approved_by_human": true`，并记录同意时间与同意原话。
3. 所有报告元信息表的“隔离模式”写同一个值，正文第一行加一句“本次为降级自查，不构成第三方评审”。
4. `scripts/egm_kit.py check` 会拦下未批准的降级；已批准的会持续给警告。

不允许为了让流程走完，把 L3 写成 L1。

## 六、写权限边界

- 评审者只读：不能写、不能改、不能建目录。
- 协调者（大象）在相 1–4 只写 `docs/designs/<设计>/` 下的产物，**不碰生产代码**。这条是约定，不是强制——所以每轮结束用 `git status` 检查一次，出现预期外的文件改动就说明边界被越过了。
- 实现相只能写 `handoff_boundary.md` 里列出的路径；越界即停，回到人那里扩清单。
